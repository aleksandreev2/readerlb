# Contributing to ReaderLB

Спасибо за интерес к ReaderLB.

## Рабочий процесс

1. Создайте issue для крупного изменения или ошибки, если контекст ещё не зафиксирован.
2. Создайте ветку от актуального `main`.
3. Используйте короткое имя: `feat/...`, `fix/...`, `docs/...` или `chore/...`.
4. Делайте изменение узким и проверяемым.
5. Запустите тесты и lint.
6. Откройте pull request в `main`.

Прямые долгоживущие разработки в `main` не используются.

## Требования к PR

PR должен:

- объяснять проблему и решение;
- не включать приватные EPUB, ключи, keystore или service-account credentials;
- сохранять существующие данные RanobeLib при обновлении тайтла;
- добавлять regression test для исправленной ошибки, когда это возможно;
- проходить GitHub Actions.

Для изменений, влияющих на storage/update/signing, укажите сценарий ручной проверки.

## Стиль

- Kotlin/Compose: придерживайтесь существующего форматирования проекта.
- Не добавляйте крупные зависимости без необходимости.
- Пользовательские сообщения приложения — на русском, если изменение не относится к техническим внутренностям.
- Комментарии в коде должны объяснять причину, а не пересказывать строку кода.

## Форматы и совместимость

Особенно аккуратно изменяйте:

- структуру локального тайтла RanobeLib;
- алгоритм обновления существующих глав;
- `.readerlb.zip`;
- signing/update chain.

Несовместимые изменения требуют отдельного плана миграции.

## Секреты

Никогда не коммитьте:

- Android release keystore;
- Firebase service-account JSON;
- GitHub tokens;
- приватные книги или пользовательские библиотеки.

`app/google-services.json` является публичной клиентской конфигурацией Firebase и не содержит серверного service-account ключа.

## Приватность данных автора

Метаданные Git-коммитов публичны. Если вы не хотите публиковать личный email:

- включите в GitHub настройку **Keep my email addresses private**;
- используйте выданный GitHub адрес вида `...@users.noreply.github.com` для локальных Git-коммитов;
- при необходимости включите **Block command line pushes that expose my email**.

Не указывайте личные контактные данные в примерах, тестовых данных, issue или commit messages без необходимости.
